# video-to-seedance-prompt

把一段参考视频**反推成可直接驱动 Seedance 2.0 的生成规格**，而不是剧情摘要。

这是一个面向 **视频复刻生产** 与 **提示词写作研究** 的 Agent Skill：原视频只作为离线分析证据，不进入生成素材映射；最终交付的是一份能用文字完整重建镜头顺序、动作因果、表情、环境运动、运镜、节奏、物理反馈、特效、声音与连续性的提示词。它还内置了一个**自我进化闭环**——把不满意的生成结果持续喂回来，Skill 会和原片逐帧比对、定位根因，并把被证据反复验证的通用经验自动沉淀回规则库。

---

## 一、它能做什么

### 1. 生产级视频复刻（三种模式，按控制力递增）

| 模式 | 交付物 | 控制力 | 准备成本 | 适用场景 |
|---|---|---|---|---|
| **图生视频** `ASSET_GUIDED_TEXT_PROMPT` | 角色/场景/首尾帧图片 + 完整文字时间线 | 中 | 低：只需准备静态图 | 大多数复刻任务；身份靠图片锁定，动态全靠文字 |
| **深度图生视频** `DEPTH_GUIDED_TEXT_PROMPT` | 编号深度故事板 + 角色图 + 文字 | 高 | 中：需从原片离线派生深度视频并抽关键帧 | 对位置、尺度、遮挡、动作相位要求高，但不需要预览颜色 |
| **深度渲染图生视频** `COLOR_STORYBOARD_GUIDED_PROMPT` | 深度故事板 → 渲染成彩色故事板 → 引导视频 | 最高 | 高：多一次图像生成 + 人工验收 | 动作复杂、VFX 多、需要先检查构图再生成视频 |

> 另有 `TEXT_ONLY_PROMPT` 纯文字模式，适合动作简单、不想准备素材的快速试验。

### 2. 视频反推提示词（个人研究向）

即使不直接生产，也可以只让它做**逐镜头拆解与提示词写作教学**：

- 把任意视频切成 shot/beat/state 中间结构，每个镜头绑定时间戳、可见证据与置信度；
- 区分**现场运动 / 摄影机运动 / 剪辑后期 / 声音 / 连续性**五条证据通道；
- 总结"提示词应该怎么写"：锚点与变化区域怎么描述、接触时序怎么表达、瞬态事件怎么给时长、怎么防止模型误读——这些都是从大量真实对比中沉淀下来的写作规则，而不是通用模板。

### 3. 自学习 / 自动升级闭环

这是这个 Skill 区别于一次性反推工具的核心：

```
原片分析 → 生成 v1 提示词 → 生视频
        ↓ （用户喂回不满意的视频）
   与原片九项对齐比对 → 定位根因（提示词错/素材冲突/抽卡/模型边界）
        ↓
   输出 v2 完整提示词 + 校准记录
        ↓
   经验三级评定：LOCAL（仅本任务） / CANDIDATE（待验证） / PROMOTED（写入 Skill 全局规则）
```

- 每轮只修 1–2 个决定性变量，不推倒重来；已正确的镜头和角色锁保留。
- 根因分类：`PROMPT_MISSING/WRONG/AMBIGUOUS/OVERLOAD`、`ASSET_CONFLICT`、`SAMPLING_VARIANCE`、`DENSITY_LIMIT`、`MODEL_LIMIT`——不把所有失败都甩给"提示词不够详细"。
- 只有**同一种误读在至少两个生成版本中重复**、或**暴露了 Skill 内部矛盾/遗漏质量门**的经验，才会被晋升为全局规则；单次抽卡、角色专属外观、固定坐标绝不晋升。
- 经验写回最窄的相关 `references/*.md`，并在项目目录维护 `复刻校准记录.md`，会话被压缩后仍能连续迭代。

    └── local-environment.md      #   本机深度模型路径记录

## 三、环境依赖

- **Python 3.10+**（脚本本身只用标准库 + ffprobe）
- **ffmpeg / ffprobe** 在 `PATH` 上
- 深度模式额外需要：
  - [Video-Depth-Anything](https://github.com/wyzor/Video-Depth-Anything)（本机已放在 `D:\github\Video-Depth-Anything`），用于把原视频离线转成无纹理深度视频；路径记在 `references/local-environment.md`
- 生成侧：Seedance 2.0 的文生视频 / 图生视频能力（Skill 只产出提示词与素材映射，不直接调用付费生成）

## 四、快速开始

### 复刻一个视频

1. 把视频丢给 Agent，说"帮我复刻这个视频"或"把这个视频反推成提示词"。
2. Skill 会跑分析流水线：探测 → 抽帧 → 切镜 → 声音对齐 → 逐镜头拆解 → 资产需求表。
3. 你在四个工作流里选一个（纯文字 / 图生视频 / 深度图生视频 / 深度渲染图生视频），按需准备图片。
4. 收到最终提示词（一个可直接复制的 fenced code block），拿去 Seedance 生成。

### 迭代不满意的结果

1. 把生成出来但不满意的视频再喂回来，说"不像 / 继续改 / 对比一下"。
2. Skill 恢复原片证据、上一版提示词、已确认素材，做九项对齐比对。
3. 交付：≤3 个主要差异 + 根因分类 + 本轮修改/保留清单 + **完整新版提示词** + 下一轮判据。
4. 被反复验证的通用规则会自动写回 `references/`，并告诉你"本轮沉淀了什么、写到哪里"。

### 只研究提示词怎么写

不传任何生成素材，只要"逐镜头拆解 + 写作规则说明"即可。Skill 会输出 shot/beat/state 中间结构和针对该片段的提示词写作要点。

## 五、设计原则（也是它和普通"视频转提示词"的区别）

- **原视频仅作分析证据**：不写 `视频1`、不"继承原视频动作/运镜"；所有动态必须由文字承担。
- **先写看见的，再解释原因**：可见几何（归一化坐标、关节位置、固定锚点 vs 变化区域）和推测机制严格分层，低置信度不写成确定动作。
- **两阶段交付**：首轮只做分析与模式确认门，不越门直接吐提示词。
- **不过度承诺**：不声称找到了原始提示词，不承诺像素级复刻；达到模型能力边界就明确标注 `MODEL_LIMIT`，不无限堆词。
- **经验晋升有门槛**：单样本、角色专属、坐标专属、审美偏好绝不晋升为全局规则。

# 生成后对照、持续修订与 Skill 校准

用于用户提供已生成视频并要求“再对比、为什么不像、继续改、可能是抽卡还是描述问题”时。目标是把当前会话变成连续实验：对齐证据、定位根因、生成下一版完整提示词，并将真正通用的经验自动沉淀回 Skill。不能因一次随机失败重写整份提示词，也不能只接受用户结论而跳过独立验证。

## 恢复当前任务状态

开始新一轮前，按以下顺序恢复上下文；已有信息不得重复询问：

1. 原片及其证据帧、镜头边界、关键状态账本。
2. 实际用于本次生成的提示词版本，而不是磁盘中名字最新但未使用的草稿。
3. 本次上传的角色图、场景图、深度板或彩色故事板及各自职责。
4. 历次生成视频、用户对每一版的反馈和已经验证有效的修正。
5. 目标时长、比例、平台、音频要求和用户明确保留的偏好。

若任务有稳定项目目录，在最近提示词所在目录维护 `复刻校准记录.md`。内容保持紧凑，使用以下字段追加一轮，不覆盖历史：

```markdown
## vN → vN+1
- 生成视频：
- 实际提示词/故事板：
- 用户反馈：
- 原片可见证据：
- 客观差异：
- 根因分类与置信度：
- 本轮修改：
- 明确保留：
- 下一轮判据：
- Skill 经验：LOCAL / CANDIDATE / PROMOTED
```

没有项目目录或用户只要口头分析时，可在当前会话内部维护同样的账本，不为此创建杂乱文件。

## 同时保留两条证据链

- 原片：仍然只作离线分析证据，不进入生成素材映射。
- 已生成版本：用于判断提示词被模型怎样解释，不自动升级为下一次生成参考。

先按原片切镜或关键事件时间建立匹配点，再在生成版本中找对应状态。不要只比较“同一秒”，因为生成版本的动作可能提前或延后。

## 九项匹配检查

逐项记录原片、生成版本、偏差和严重度：

1. 切镜时刻与镜头数量。
2. 第一帧人物位置、画面占比和朝向。
3. 固定锚点是否稳定，主要变化区域是否正确。
4. 动作轮廓、轨迹、角度和速度变化。
5. 预接触间隙与首次接触时间。
6. 压缩、保持接触、分离和落地的先后顺序。
7. 冲击帧、抽帧、负片、残影等后期事件的进入、持续和退出。
8. 场景、色彩或环境状态何时切换，旧状态是否错误残留。
9. 最终姿态、屏幕位置、到达时间和保持时长。

每项差异用四列记录：`原片可见状态 / 生成状态 / 偏差 / 证据时间点`。动作提前或延后时按事件对齐，不机械比较同一秒。优先选三个最影响相似度的差异，不让次要色彩或粒子装饰掩盖姿态、构图和动作因果错误。

## 处理用户反馈

用户反馈是诊断入口，不是未经验证的最终结论。逐条执行：

1. 原样保留用户指出的症状，例如“膝盖不够靠右”“没有慢慢弯曲发力”“人物只是变暗而非纯黑”。
2. 转成可检查指标，例如膝盖 `x%`、屈曲趋势、到达时点、旧颜色是否完全消失。
3. 在原片、故事板、提示词和生成视频中分别寻找对应证据，确定问题最早出现在哪一层。
4. 用户反馈正确时扩大检查到相邻状态，找出根因而非只加入一句禁止词；用户描述与画面不完全一致时，说明可见证据并修正为更准确的表达。
5. 用户只说“效果差”时，主动完成九项检查，不把诊断责任退回给用户。

## 原因分类

给每个主要偏差选择最可能的类别，不把所有失败都归因于提示词：

- `PROMPT_SYSTEMIC`：同一偏差在多次生成或多个相邻时段稳定出现；提示词存在错误机制、歧义、冲突或缺少锚点。
- `SAMPLING_VARIANCE`：提示词约束已经明确，但错误的部位、方向或形式在不同生成中随机变化；优先建议重试，不改核心动作。
- `ASSET_CONFLICT`：角色图的姿势、长发、尾巴、鞋靴、道具或背景持续覆盖文字要求，改变动作轮廓或画面权重；缩小该图片职责并明确不得继承项。
- `DENSITY_LIMIT`：短时长内镜头、动作、特效和声音过多，模型稳定合并或遗漏后半段；删除次要信息或降低每镜状态变化数。
- `MODEL_LIMIT`：在提示词简化、资产职责清楚且多次重试后，同一复杂交互仍无法稳定生成；如实说明限制，不继续堆词。

对提示词问题再细分，以决定修法：

- `PROMPT_MISSING`：原片中的决定性状态、路径、时间或退出条件根本没有写。
- `PROMPT_WRONG`：文字与原片证据相反，或错误解释了人体机制。
- `PROMPT_AMBIGUOUS`：文字可以同时支持正确与错误画面，缺少屏幕拓扑、优先级或瞬态时长。
- `PROMPT_OVERLOAD`：关键信息存在，但被重复风格词、过多事件或冲突指令稀释。
- `BOARD_ERROR`：深度板或彩色板已经画错、趋势反转、肢体不可辨或某个瞬态被固化；不能只靠文字与错误图片对抗。

一次结果不足以证明抽卡或系统性问题。只有一个样本时使用“更可能”并说明依据；有多个样本时检查偏差是否重复。

## 修订纪律

1. 先列影响最大的三个差异，按动作因果、空间构图、时间预算、特效装饰排序。
2. 已经正确的镜头、角色锁和节奏不重写；每轮只调整一至两个主要变量。
3. 删除被证伪的机制描述，改成可见几何；不要在旧错误上继续叠加负面词。
4. 每条禁止项同时给出正向替代行为，例如“头肩保持右上不动，只有前景腿部轮廓连续铺开；禁止整个人物向镜头飞来”。
5. 提示词本身正确而输出只出现一次随机偏差时，保留提示词并建议重试。
6. 修订后重新核对切镜、接触顺序、环境状态和终态保持，防止修复局部后破坏已正确部分。
7. 将已证实为通用误读的问题回填到 [first-pass-reliability.md](first-pass-reliability.md) 的预检类别；不要把某个角色、某个角度或单次采样故障写成全局硬规则。

## 每轮固定输出

每次校准至少交付：

1. 三个以内的主要差异及证据。
2. 每个差异的根因类别与置信度。
3. “本轮修改 / 明确保留 / 暂不修改”清单。
4. 可直接复制或落盘的完整新提示词；不能只给追加句，因为旧版冲突可能仍在。
5. 下一轮只需检查的明确判据，例如“0.8秒时膝盖进入画面右侧90%区域，释放前持续右移且不提前伸直”。
6. 本轮是提示词系统性修复、故事板修复、建议重抽，还是模型边界判断。

如果故事板本身错误，先修故事板及其生成描述，再同步修视频提示词；如果故事板正确而文字缺失，只修文字；如果二者都正确且错误不稳定，优先重试，不制造更多约束。

## 通用经验自动晋升

每轮把新经验标为三级：

- `LOCAL`：只适用于当前角色、服装、镜头、角度、坐标或用户审美，留在 `复刻校准记录.md`。
- `CANDIDATE`：看起来可复用，但只有单次结果或根因仍有竞争解释，暂不修改 Skill。
- `PROMOTED`：可复用且证据充分，自动写入 Skill。

满足以下任一条件才可晋升为 `PROMOTED`：

- 同一种误读在至少两个生成版本中重复，且能追溯到相同的提示词缺陷。
- 用户指出后，原片、提示词和生成结果形成直接证据链，证明缺少一个普适的表达规则，而非主观偏好。
- 当前失败暴露了现有 Skill 内部的矛盾、遗漏的质量门或素材职责冲突，修正规则不会绑定特定角色与镜头。

以下内容不得自动晋升：单次随机畸形、某角色的服装细节、某个固定坐标/角度/时间戳、供应商偶发故障、未经比较的用户猜测、只对当前审美有效的风格偏好。

晋升时：

1. 写成能改变未来决策的通用规则，去掉角色名、文件名、具体镜头坐标和案例叙述。
2. 修改最窄的相关 reference；只有新增路由、触发条件或全局质量门时才修改 `SKILL.md`。
3. 优先补充已有规则，不重复堆叠同义条款。
4. 使用 skill-creator 的 `quick_validate.py` 校验整个 Skill。
5. 向用户简短报告“本轮沉淀了什么、写入哪里”；如果没有足够证据晋升，也明确说明仅保留为当前任务校准。

## 停止与继续条件

- 新版本解决了主要差异：保留本轮修订，并等待用户的新生成结果继续闭环。
- 提示词与素材已明确，但单次输出随机偏离：建议用原提示词重试一至两次，不继续加词。
- 多次输出稳定出现同一错误：继续定位并修复系统性根因。
- 简化提示词、消除素材冲突并重试后仍无法稳定实现：标为 `MODEL_LIMIT`，建议换工作流、拆镜头或接受误差；未经用户授权不自动扩大生产范围。
